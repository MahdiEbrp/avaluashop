# اتصال درگاه تاباپی

این پروژه از API رسمی تاباپی استفاده می‌کند؛ نه از افزونهٔ وردپرس.

## تنظیمات محیط

مقادیر زیر را فقط در متغیرهای محیطی سرور (برای نمونه در تنظیمات پروژهٔ Vercel) قرار دهید:

- `TABAPAY_MERCHANT_KEY`: کلید مرچنت دریافتی از پنل تاباپی. این مقدار محرمانه است و نباید در کد فرانت‌اند یا Git قرار بگیرد.
- `TABAPAY_SANDBOX=true`: حالت پیش‌فرض و امن برای آزمایش.
- `APP_URL`: نشانی اصلی سایت، مانند `https://avaluashop.vercel.app`.

تا پایان آزمون‌های انتها‌به‌انتها، `TABAPAY_SANDBOX` را روی `true` نگه دارید. برای تراکنش عملیاتی، تغییر آن به `false` فقط پس از تأیید حساب پذیرندگی و تنظیمات از سوی صاحب قانونی کسب‌وکار انجام شود.

## چرخهٔ سفارش

1. سرور نشانی متعلق به کاربر، سبد، قیمت‌ها و موجودی را بررسی می‌کند.
2. سفارش با وضعیت `PendingPayment` ساخته و موجودی در همان تراکنش رزرو می‌شود.
3. سرور مبلغ ذخیره‌شده به تومان را به ریال تبدیل می‌کند و به `/v1/sandbox/create` یا `/v1/create` می‌فرستد.
4. مرورگر فقط به نشانی HTTPS معتبر متعلق به `api.tabapay.ir` هدایت می‌شود.
5. پس از بازگشت، سرور با توکن و مبلغ مورد انتظار، API تأیید تاباپی را فراخوانی می‌کند.
6. فقط پاسخ موفقِ تأییدشده با همان توکن و همان مبلغ، پرداخت و سفارش را نهایی می‌کند. callback تکراری idempotent است.
7. در پاسخ ناموفق قطعی، سفارش لغو و موجودی رزروشده بازگردانده می‌شود. خطای شبکه یا مغایرت مبلغ/توکن به‌عنوان شکست قطعی تلقی نمی‌شود و برای بررسی باقی می‌ماند.

سبد خرید تا تأیید پرداخت دست‌نخورده می‌ماند؛ هنگام موفقیت فقط تعداد اقلام خریداری‌شده از سبد کم می‌شود.

## نکات عملیاتی مهم

- API تاباپی مبلغ را به **ریال** می‌پذیرد؛ قیمت‌های فعلی فروشگاه به **تومان** نمایش داده می‌شوند، بنابراین تبدیل در سرور انجام می‌شود.
- محدودهٔ مستندشدهٔ هر تراکنش تاباپی ۱۰۰٬۰۰۰ تا ۵۰۰٬۰۰۰٬۰۰۰ ریال است.
- هزینهٔ ارسال در حال حاضر صفر است و کد تخفیف صرفاً اعتبارسنجی می‌شود؛ هنوز از مبلغ نهایی کسر نمی‌شود.
- سفارش‌های رهاشده در وضعیت انتظار پرداخت، تا زمان دریافت callback یا رسیدگی پشتیبانی، موجودی را رزرو نگه می‌دارند. پیش از بهره‌برداری واقعی باید سیاست انقضای سفارش و تطبیق تراکنش‌های بی‌پاسخ با پشتیبانی تاباپی اضافه شود.
- پس از تغییر enum در Prisma، پیش از انتشار باید `npm run db:push` روی پایگاه دادهٔ هدف اجرا و سپس `npm run db:generate` انجام شود.
- هیچ کلید مرچنت واقعی یا اطلاعات حساب بانکی را در issue، PR، فایل env نمونه یا پیام عمومی قرار ندهید.
