# تنظیمات پرداخت، ارسال و مالیات

تنظیمات فروشگاه از دیتابیس مدیریت می‌شوند و از مسیر «مدیریت ← تنظیمات» قابل تغییر هستند.

## کلید رمزنگاری

کلید پذیرندهٔ درگاه در دیتابیس به‌صورت رمزنگاری‌شده با AES-256-GCM نگهداری می‌شود. پیش از فعال‌سازی ذخیرهٔ اطلاعات درگاه، متغیر زیر را در محیط سرور (از جمله Vercel) تنظیم کنید:

- `APP_SETTINGS_ENCRYPTION_KEY`: کلید ۳۲ بایتی Base64 یا ۶۴ کاراکتر hex. برای تولید: `openssl rand -base64 32`.

این کلید را در Git، کد مرورگر یا پیام عمومی قرار ندهید. از دست‌دادن یا تغییر آن باعث می‌شود اعتبارنامه‌های رمزنگاری‌شدهٔ قبلی قابل بازیابی نباشند.

## تنظیم درگاه

1. وارد پنل مدیریت شوید و به «تنظیمات» بروید.
2. کلید پذیرنده را وارد کنید؛ کلید خام به مرورگر بازگردانده نمی‌شود.
3. حالت Sandbox را فعال نگه دارید و درگاه را برای آزمایش روشن کنید.
4. پس از تست کامل و تأیید حساب پذیرندگی توسط مسئول قانونی کسب‌وکار، در صورت نیاز Sandbox را غیرفعال کنید.

در این نسخه adapter عملیاتی تاباپی است. مدل دیتابیس برای افزودن providerهای دیگر آماده شده، اما افزودن هر درگاه جدید همچنان به adapter اختصاصی، verify امن و تست نیاز دارد.

## مالیات و ارسال

- نرخ و عنوان مالیات از رکورد یکتای `StoreSetting` خوانده می‌شوند.
- روش‌های ارسال از `ShippingMethod` خوانده شده و در پنل مدیریت قابل ایجاد، فعال/غیرفعال‌سازی و حذف هستند.
- اگر حداقل مبلغ ارسال رایگان تعریف شود، مبلغ کالاها پس از تخفیف محصول برای سنجش آستانه استفاده می‌شود.
- مالیات، هزینه ارسال، نرخ مالیات و نام روش ارسال هنگام ساخت سفارش در خود سفارش snapshot می‌شوند؛ تغییر تنظیمات بعدی، سفارش‌های قبلی را تغییر نمی‌دهد.
- واحد محاسبات داخلی فروشگاه تومان (IRT) است. adapter درگاه مبلغ نهایی را به ریال تبدیل می‌کند.

## انتشار تغییرات دیتابیس

این تغییرات Prisma schema جدید دارند. پیش از استقرار نسخهٔ جدید، روی دیتابیس هدف اجرا کنید:

```bash
npm run db:push
npm run db:generate
```

ابتدا روی محیط آزمایشی اجرا و سفارش آزمایشی را از ابتدا تا انتها بررسی کنید. اجرای `db:push` روی دیتابیس production باید با پشتیبان‌گیری و تأیید مسئول فنی انجام شود.

## چرخهٔ پرداخت

1. سرور مالکیت نشانی، سبد، قیمت و موجودی را بررسی می‌کند.
2. سفارش با وضعیت `PendingPayment` ایجاد و موجودی کالا و کد تخفیف در همان تراکنش رزرو می‌شود.
3. سرور مبلغ ذخیره‌شده به تومان را به ریال تبدیل کرده و به API تاباپی می‌فرستد.
4. مرورگر فقط به نشانی HTTPS معتبر متعلق به `api.tabapay.ir` هدایت می‌شود.
5. پس از بازگشت، سرور با توکن و مبلغ مورد انتظار، API تأیید تاباپی را فراخوانی می‌کند.
6. فقط پاسخ موفق با همان توکن و مبلغ، سفارش را نهایی می‌کند.
7. پاسخ ناموفق قطعی باعث آزادسازی رزرو می‌شود؛ خطای شبکه یا پاسخ مبهم به‌عنوان شکست قطعی تلقی نمی‌شود.

سفارش‌های دارای نتیجهٔ مبهم هنوز به فرایند reconciliation خودکار نیاز دارند و تا بررسی، رزرو موجودی را نگه می‌دارند. تا زمان پیاده‌سازی آن و تست کامل، پرداخت عملیاتی را فعال نکنید.
