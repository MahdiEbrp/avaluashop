# روش‌های ارسال

## روش‌های قابل استفاده در checkout

روش‌ها در مدل `ShippingMethod` ذخیره می‌شوند و از پنل `/admin/shipping` قابل مدیریت‌اند:

- `FlatRate`: مبلغ ثابت به تومان.
- `Free`: بدون هزینه ارسال.
- `FreeAbove`: رایگان‌شدن ارسال پس از رسیدن مبلغ سبد (پس از تخفیف محصولات و کد تخفیف) به آستانه.
- `allowedCities`: فهرست اختیاری شهرهای مجاز؛ فهرست خالی به معنی همه شهرهاست.

روش‌های غیرفعال در API عمومی برگردانده نمی‌شوند. حذف از پنل، حذف فیزیکی نیست و روش را غیرفعال می‌کند تا ارتباط و نام ثبت‌شده در سفارش‌های قبلی باقی بماند.

## کدهای خطای ثبت سفارش

مرورگر پاسخ `POST /api/orders` را هم به شکل متن ساده و هم JSON می‌خواند و کد را به پیام فارسی تبدیل می‌کند:

| کد | معنا |
| --- | --- |
| `SHIPPING_METHOD_REQUIRED` | روش فعال وجود دارد اما هیچ روشی انتخاب نشده است. |
| `SHIPPING_METHOD_UNAVAILABLE` | روش انتخاب‌شده حذف، غیرفعال یا برای همان شهر غیرمجاز شده است. |
| `SHIPPING_NOT_AVAILABLE_FOR_CITY` | برای شهر نشانی انتخاب‌شده هیچ روش فعالی وجود ندارد. |

اگر برای شهر نشانی هیچ روشی موجود نباشد، checkout پیام «برای شهر این نشانی روش ارسال فعالی وجود ندارد.» را نشان می‌دهد و ثبت سفارش را متوقف می‌کند؛ سرور هم همان سفارش را با `SHIPPING_NOT_AVAILABLE_FOR_CITY` رد می‌کند.

## تطبیق نام شهر

`allowedCities` و شهر نشانی پیش از مقایسه نرمال می‌شوند (`normalizeCity`):

- حروف عربی و فارسی هم‌شکل یکی می‌شوند: `ي/ی`، `ك/ک`، `أ/إ/آ/ٱ→ا`، `ة/ۀ→ه`.
- نیم‌فاصله (ZWNJ) و کشیده (U+0640) حذف می‌شوند.
- ارقام فارسی ۰-۹ و عربی ٠-٩ به ارقام لاتین تبدیل می‌شوند.
- فاصله‌های تکراری یکی می‌شوند و مقایسه بدون حساسیت به بزرگی/کوچکی حرف انجام می‌شود.

در پنل، فیلد «شهرهای مجاز» با کاما، ویرگول فارسی «،»، نقطه‌ویرگول و خط جدید جدا می‌شود (`parseAllowedCities`) و مقدار خالی به معنی همه شهرهاست. روش‌های `CarrierCalculated` فقط از طریق API قابل ساخت‌اند و دکمهٔ ویرایش‌شان در پنل غیرفعال است؛ فرم ویرایش با `editableMethodType` فقط انواع دستی را می‌پذیرد.

## محاسبه مبلغ سفارش

مبلغ نهایی فقط در `POST /api/orders` و داخل تراکنش سرور محاسبه می‌شود. کلاینت فقط شناسه روش ارسال را می‌فرستد؛ قیمت، وضعیت فعال‌بودن و شهر مجاز دوباره از دیتابیس خوانده می‌شوند.

ترتیب محاسبه:

1. جمع قیمت کالاها و تخفیف محصولات
2. تخفیف کد معتبر
3. بررسی آستانه ارسال رایگان بر مبلغ پس از تخفیف
4. مالیات تنظیم‌شده در `StoreSetting` روی مبلغ کالا پس از تخفیف (هزینه ارسال در این مرحله مشمول مالیات نیست)
5. افزودن هزینه ارسال به مبلغ قابل پرداخت

نرخ اعمال‌شده در `Order.taxRateSnapshot` ذخیره می‌شود تا سفارش قدیمی با تغییر نرخ مالیات بازنویسی نشود.

اگر هیچ روش فعالی تعریف نشده باشد، هزینه ارسال صفر خواهد بود. اگر دست‌کم یک روش فعال وجود داشته باشد، انتخاب روش معتبر برای ثبت سفارش الزامی است.

## کد رهگیری مرسوله (دستی)

در حال حاضر کد رهگیری دستی ثبت می‌شود: در `/admin/orders/<id>` فیلد «شماره مرسوله / کد رهگیری» مقدار `Order.shippingTrackingNumber` را تنظیم می‌کند.

- `PATCH /api/admin/orders/<orderId>` فیلد را می‌پذیرد: رشتهٔ حداکثر ۱۰۰ کاراکتر، trim می‌شود، و رشتهٔ خالی یا فقط فاصله به `NULL` تبدیل می‌شود تا «کد پاک‌شده» با «کد ثبت‌نشده» یکی باشد.
- فیلدهای ناشناخته در بدنهٔ PATCH نادیده گرفته می‌شوند. API سفارش دیگر اجازهٔ تغییر مستقیم `isPaid` یا مبالغ سفارش را نمی‌دهد؛ تأیید پرداخت فقط از مسیر callback تأییدشدهٔ درگاه انجام می‌شود.
- مشتری در `/profile/orders/<id>` روش ارسال، شرکت حمل‌ونقل، وضعیت فارسی سفارش و کد رهگیری را می‌بیند؛ اگر کد ثبت نشده باشد پیام «کد رهگیری هنوز ثبت نشده است.» نمایش داده می‌شود.

## گردش وضعیت سفارش

- `PendingPayment` و وضعیت‌های پرداخت، لغو و مرجوعی از این فرم قابل تغییر نیستند؛ این وضعیت‌ها به جریان‌های پرداخت یا فرایندهای اختصاصی خود تعلق دارند.
- سفارش پرداخت‌شده از `Processing` به `Shipped` می‌رود و برای این انتقال کد رهگیری غیرخالی لازم است.
- سفارش `Shipped` می‌تواند به `Delivered` تغییر کند؛ در این مرحله `isCompleted` نیز توسط سرور فعال می‌شود.
- API با به‌روزرسانی شرطی وضعیت قبلی، از اعمال هم‌زمان تغییرات متناقض جلوگیری می‌کند.
- لغو سفارش پرداخت‌شده و بازپرداخت هنوز گردش مستقل ندارند و نباید با تغییر دستی وضعیت شبیه‌سازی شوند.

## شرکت‌های حمل‌ونقل

مدل‌های `ShippingCarrier` و enumهای Post، Tipax و Chapar در schema وجود دارند، اما این مرحله اتصال API عملیاتی یا استعلام زنده کرایه را پیاده‌سازی نمی‌کند. روش نوع `CarrierCalculated` تا زمان وجود adapter مستند، احراز هویت و آزمون انتها‌به‌انتها در checkout غیرقابل انتخاب می‌ماند. برای راه‌اندازی carrierها باید هر ارائه‌دهنده جداگانه با مستندات رسمی، کلیدهای متعلق به صاحب حساب و تست sandbox پیاده‌سازی شود.

## استقرار

این تغییر schema جدیدی اضافه نمی‌کند. مطابق سیاست مخزن، پس از ادغام روی محیط مقصد `npm run db:push` اجرا شود؛ از Prisma Migrate یا ساخت پوشه migrations استفاده نکنید.
